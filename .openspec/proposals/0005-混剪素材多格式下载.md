# 0005 - 混剪素材多格式下载：合并 MP4 + 所有片段 ZIP

- **状态**: draft
- **创建日期**: 2026-05-14

## 背景

当前混剪/千川重排链路在下载时只面向“最终成片”交付：系统按选中的字幕/轨道片段把素材整合导出为一个 MP4 文件。这个结果适合直接投放或预览，但不适合二次剪辑：业务想拿到每个素材段落独立文件时，需要手工回到原视频逐段裁切。

用户本期明确收敛后的诉求：

1. 保留当前“整合为一个素材 MP4 文件”的合并下载能力。
2. 新增“分开下载”：下载一个 ZIP，ZIP 内包含所有混剪片段，每个 MP4 按素材段落命名。
3. 剪映可编辑草稿本期先不考虑。

## 目标

1. 下载入口支持明确的导出格式：
   - `merged_mp4`：输出当前行为的单个合并 MP4。
   - `segments_zip`：输出一个 ZIP，里面包含所有素材段落单独裁切后的 MP4。
2. 分段 ZIP 中的文件名可读、稳定、不会包含危险路径字符；优先使用段落顺序 + 段落摘要/字幕关键词 + 时间范围命名。
3. 分段文件必须与当前混剪顺序和时间范围一致，避免“ZIP 里的段落”和“合并 MP4 里的顺序/内容”不一致。
4. 前端下载按钮从单一“下载”升级为“合并下载 MP4 / 分开下载 ZIP”。
5. 保持现有 API 和页面兼容；老下载入口默认仍下载合并 MP4。

## 非目标

- 不重写混剪/千川重排算法。
- 不实现剪映/CapCut 草稿导出。
- 不引入云端剪映官方 API。
- 不改变素材审核启用/禁用逻辑，只复用当前最终选中的片段列表。

## 方案

### 1. 后端导出格式参数

在现有混剪/导出下载接口上新增格式参数，建议命名为 `format` 或 `download_mode`：

| 值 | Content-Type | 文件名示例 | 说明 |
|---|---|---|---|
| `merged_mp4` | `video/mp4` | `run_id-remix.mp4` | 保持当前合并导出行为 |
| `segments_zip` | `application/zip` | `run_id-segments.zip` | 所有片段各一个 MP4 |

如果需要兼容旧入口：未传参数时默认 `merged_mp4`。

### 2. 分段 ZIP 生成

新增导出 helper，例如：

```python
def export_segments_zip(run_dir: Path, segments: list[SegmentRef], output_zip: Path) -> Path: ...
```

实现要点：

1. 复用当前合并 MP4 所使用的最终片段列表，包含源视频路径、开始时间、结束时间、排序后的段落序号。
2. 每个段落用 FFmpeg 单独裁切为临时 MP4，再写入 ZIP。
3. 文件名格式建议：

   ```text
   001_00-00-12.300_00-00-18.900_段落摘要.mp4
   002_00-01-03.000_00-01-09.500_段落摘要.mp4
   ```

4. 文件名清洗规则：
   - 只保留中文、英文、数字、空格、`-`、`_`。
   - 连续空白折叠为 `_`。
   - 摘要最长 24 个字符；为空时使用 `segment`。
   - 所有 ZIP entry 禁止绝对路径和 `..`。
5. ZIP 内额外写入 `manifest.json`，用于记录原始片段元数据：

   ```json
   {
     "schema_version": 1,
     "segments": [
       {
         "index": 1,
         "file": "001_...mp4",
         "source_start": 12.3,
         "source_end": 18.9,
         "text": "...",
         "summary": "..."
       }
     ]
   }
   ```

6. 失败处理：任一片段裁切失败时，删除半成品 ZIP，接口返回 500 和明确错误信息，不返回不完整 ZIP。

### 3. 前端交互

在现有混剪/任务结果页把单一下载入口调整为：

1. **合并下载 MP4**：默认主按钮，行为不变。
2. **分开下载 ZIP**：新按钮，下载所有分段 MP4 包。

### 4. 缓存与产物目录

建议把导出产物落在 run 目录下，避免重复点击反复生成：

```text
data/runs/<run_id>/exports/
├── remix.mp4
└── segments.zip
```

当 `timeline_overrides.json`、remix 结果或相关 metadata 的修改时间晚于导出产物时，应重新生成；否则直接复用缓存文件。

## 验收标准

1. **兼容旧行为**：不传格式参数时，下载结果仍为当前合并 MP4。
2. **合并下载**：`format=merged_mp4` 返回 `video/mp4`，文件可播放，内容与当前导出一致。
3. **分开下载**：`format=segments_zip` 返回 ZIP；ZIP 内每个启用/混剪片段对应一个 MP4，并包含 `manifest.json`。
4. **命名正确**：ZIP 内 MP4 按 `001_...mp4` 顺序命名，包含段落信息，且不包含 `/`、`\`、`..`、控制字符等危险内容。
5. **顺序一致**：ZIP 内 `manifest.json.segments[*]` 的顺序与合并 MP4 拼接顺序一致。
6. **失败不产出半成品**：模拟某个片段裁切失败时，不保留损坏 ZIP，接口返回明确错误。
7. **前端可用**：页面能分别触发合并 MP4 与分段 ZIP 下载。
8. **测试通过**：相关单测通过，且 `python -m unittest discover` 不因本次改动失败。
