# 0006 - 多混剪方案生成与展示命名优化

- **状态**: draft
- **创建日期**: 2026-05-14

## 背景

当前业务自助成片任务的 Remix/混剪链路一次只生成一个成片方案。业务在同一批素材上往往希望一次拿到多个不同排序/脚本结构的混剪方案，用于快速对比和挑选，而不是反复创建任务或反复点击生成。

同时，当前业务页面里的展示命名偏工程化，例如“日志”“Remix 轨道”。业务侧更希望看到明确的成片语义：Remix 结果应称为“成片预览”。

## 目标

1. 创建任务表单上增加“混剪方案数”配置，业务可指定 LLM 一次生成几个混剪方案。
2. 后端任务执行时按配置生成多个方案，每个方案都导出独立 MP4，并保留对应 plan JSON。
3. 任务结果中能展示多个“成片预览方案”，每个方案可预览、合并下载 MP4、分开下载 ZIP。
4. 页面展示命名优化：
   - “Remix 轨道”改为“成片预览”。
   - “日志”不作为业务主标签名；可以改为“处理过程”或放到次级区域。
5. 保持默认行为兼容：未配置时仍生成 1 个方案。

## 非目标

- 不改变 enabled 初剪轨道生成逻辑。
- 不要求 LLM 一次请求返回多个方案；可以用多次 LLM 调用实现，只要对用户表现为一次任务生成多个方案。
- 不做方案优劣自动排序评分，本期仅按生成顺序展示。
- 不做多方案之间的素材去重或强制差异化算法；可通过 prompt 提示尽量差异化。
- 不重做审核台的复杂交互，仅补业务自助页和必要 API 数据。

## 方案

### 1. 创建任务参数

在业务任务的 `remix` 配置中新增字段：

```json
{
  "remix": {
    "target_duration": 25,
    "use_llm": true,
    "stream": false,
    "model": null,
    "plan_count": 3
  }
}
```

约束建议：

| 字段 | 默认值 | 范围 | 说明 |
|---|---:|---:|---|
| `plan_count` | 1 | 1~5 | 单次任务生成的混剪方案数 |

前端表单增加数字输入：`混剪方案数`，默认 1，最小 1，最大 5。仅在勾选“千川 remix / 成片预览”时显示或生效。

### 2. 后端生成多个方案

任务 runner 当前 remix 流程可扩展为循环：

1. 构建一次 `remix_source`。
2. 对 `range(plan_count)` 逐个生成 plan：
   - `use_llm=true`：调用 LLM 生成 `ordered_ids`。
   - `use_llm=false`：第一个方案使用 `default_plan`；后续如果没有差异化本地策略，可复用默认方案并在 plan 中标记 `duplicate_of_default=true`，或限制为 1 个。
3. 每个方案导出独立 MP4：

```text
exports/<job_id>_remix_25s_v1.mp4
exports/<job_id>_remix_25s_v2.mp4
exports/<job_id>_remix_25s_v3.mp4
metadata/<job_id>_remix_25s_v1_plan.json
metadata/<job_id>_remix_25s_v2_plan.json
metadata/<job_id>_remix_25s_v3_plan.json
```

4. job artifacts 新增结构化字段：

```json
{
  "remix_plans": [
    {
      "index": 1,
      "label": "方案 1",
      "mp4": "...v1.mp4",
      "plan": "...v1_plan.json",
      "duration": 24.8,
      "ordered_ids": ["s001", "s008"]
    }
  ],
  "remix_mp4": "...v1.mp4"
}
```

`remix_mp4` 保留为第一个方案路径，兼容旧前端/旧接口。

### 3. 多方案差异化提示

如果使用多次 LLM 调用，建议在每次调用时追加轻量约束：

- 第 1 个方案：常规爆款结构。
- 第 2 个方案：更强调卖点密度。
- 第 3 个方案：更强调产品外观/场景。
- 第 4/5 个方案：更强调促单或礼赠场景。

本期可以先在 prompt 后附加“这是第 N 个方案，请尽量避免与前面方案完全相同”的文本；若 LLM 返回重复 `ordered_ids`，仍保存，但在 plan 中标记 `duplicate=true`。

### 4. 前端展示

业务自助页结果详情调整：

1. tab 文案：
   - `日志` → `处理过程`
   - `Remix 轨道` → `成片预览`
   - `Enabled 轨道` 可保持或后续改为 `初剪轨道`（本期可顺手改为 `初剪轨道`，更业务化）。
2. 成片预览区域展示多个方案卡片或下拉：
   - 每个方案一个 `<video>` 或一个方案选择列表 + 单个播放器。
   - 每个方案提供：预览、合并下载 MP4、分开下载 ZIP。
3. 若只有一个方案，展示形式仍保持简洁，不增加业务负担。

### 5. artifacts 下载

继续复用现有 artifacts 路由：

- MP4：直接返回对应方案的 mp4 文件。
- ZIP：按方案 plan 动态生成或缓存：

```text
exports/<job_id>_remix_25s_v1_segments.zip
exports/<job_id>_remix_25s_v2_segments.zip
```

默认旧名称 `<job_id>_remix_segments.zip` 可继续指向第一个方案，保持兼容。

## 验收标准

1. **默认兼容**：不配置 `plan_count` 时，任务仍只生成 1 个成片预览方案，旧 `remix_mp4` 字段存在。
2. **配置生效**：创建任务时 `plan_count=3` 且 `use_llm=true`，任务成功后 artifacts 中有 3 个 `remix_plans` 条目。
3. **文件产出**：每个方案都有独立 MP4 和 plan JSON，文件名包含方案序号。
4. **前端展示**：任务详情中显示“处理过程”“初剪轨道”“成片预览”，不再显示“日志”“Remix 轨道”。
5. **多方案操作**：每个成片预览方案都可以预览、合并下载 MP4、分开下载 ZIP。
6. **范围限制**：`plan_count < 1` 或 `plan_count > 5` 请求被校验拒绝，前端输入也限制 1~5。
7. **测试通过**：相关单测通过，且 `python -m unittest discover` 不因本次改动失败。

## 备注

- 如果 LLM 成本或耗时较高，可以后续加并发/异步生成；本期优先保证串行稳定。
- “日志”是否彻底隐藏还是改为“处理过程”，本 proposal 建议先改名保留，方便排查任务失败原因。
